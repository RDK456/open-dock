# macOS media controls research

Scope: Tauri 2 / Rust companion, current media actions (play/pause, next/previous, volume/mute), and the phone's play-state icon.

## Recommendation

- Reuse the existing `enigo` media-key actions on macOS: `MediaPlayPause`, `MediaNextTrack`, `MediaPrevTrack`, `VolumeUp`, `VolumeDown`, and `VolumeMute`. Enigo 0.6.1 documents those key variants and its changelog specifically notes that macOS media-control keys were added. This is the smallest cross-platform implementation; verify the packaged app's Accessibility/input permission flow on real Macs. [Enigo `Key`](https://docs.rs/enigo/0.6.1/enigo/enum.Key.html) · [Enigo 0.6.1 changelog](https://docs.rs/crate/enigo/0.6.1/source/CHANGES.md)
- Do **not** promise authoritative, global playback-state reporting on macOS. Apple's `MPNowPlayingInfoCenter.playbackState` describes the state of the app's own playback, and `MPRemoteCommandCenter` handles commands delivered to the app designated to receive them. Apple's external-player guidance says the receiving app must be the Now Playing app. These APIs do not expose a general API for a companion to inspect every other app's playback state. Keep the macOS state `unavailable` unless Open Dock owns the player or adds explicit per-app integrations; keep the phone's tap feedback optimistic. [MPNowPlayingInfoCenter playback state](https://developer.apple.com/documentation/mediaplayer/mpnowplayinginfocenter/playbackstate) · [MPRemoteCommandCenter](https://developer.apple.com/documentation/mediaplayer/mpremotecommandcenter) · [Handling external player events](https://developer.apple.com/documentation/mediaplayer/handling-external-player-events-notifications)
- Target **macOS 10.15 Catalina or later** for the first release. Tauri's current prerequisites require Catalina or later for development, although its bundle default is 10.13; Open Dock's Tauri config now explicitly sets 10.15. This is a product/build target for a multi-release range, not a minimum imposed by the media-key path. [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/) · [Tauri macOS bundle minimum version](https://v2.tauri.app/distribute/macos-application-bundle/)

## Controls and limits

| Action | macOS path | Caveat |
| --- | --- | --- |
| Play/pause, next, previous | Enigo media key events | These are commands, not a queryable session handle. Individual apps may ignore a command or choose which player responds. |
| Volume up/down/mute | Enigo system volume media keys | Prefer these for system UX and device compatibility. Core Audio device volume/mute properties are per-device and may be absent or read-only; Apple's guidance says to check property support and writability before setting. [Core Audio device model](https://developer.apple.com/documentation/coreaudio/audiohardwaredevice) · [Apple QA1016](https://developer.apple.com/library/archive/qa/qa1016/_index.html) |
| Current global playback state | No general public API found | Do not infer `playing` from command success. Use `unavailable` or add documented app-specific integrations. `MPNowPlayingInfoCenter` is for publishing the caller app's own now-playing metadata/state. |

## Permission and compatibility notes

- Enigo prompts/checks for Accessibility permission when creating its input connection; Open Dock now tells Mac users where to grant permission and returns a specific error to the phone if a control is denied. [Enigo 0.6.1 source](https://docs.rs/crate/enigo/0.6.1/source/src/macos/macos_impl.rs) · [Apple `AXIsProcessTrustedWithOptions`](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions)
- Apple's local-network privacy docs require `NSLocalNetworkUsageDescription` for apps that use direct local-network connections; Open Dock now supplies this description in the merged Tauri `Info.plist`. [Apple `NSLocalNetworkUsageDescription`](https://developer.apple.com/documentation/bundleresources/information-property-list/nslocalnetworkusagedescription) · [Tauri native configuration](https://v2.tauri.app/distribute/macos-application-bundle/)
- Avoid AppleScript as the generic fallback: automation to another app requires user approval on macOS 10.14+, and apps using Apple Events need `NSAppleEventsUsageDescription`; sandboxing also restricts sending Apple Events to arbitrary apps. App-specific support can be added later with its own permissions and app-by-app behavior. [macOS 10.14 release notes](https://developer.apple.com/documentation/macos-release-notes/macos-mojave-10_14-release-notes/) · [NSAppleEventsUsageDescription](https://developer.apple.com/documentation/bundleresources/information-property-list/nsappleeventsusagedescription) · [App Sandbox restrictions](https://developer.apple.com/documentation/security/protecting-user-data-with-app-sandbox)
- Apple documents Core Audio's default output device and device property model, but a device's volume/mute support is not universal. The established scalar volume selector is a device control, not a guarantee of a single writable system master-volume control. [Core Audio](https://developer.apple.com/documentation/coreaudio) · [Volume scalar selector](https://developer.apple.com/documentation/coreaudio/kaudiodevicepropertyvolumescalar) · [Mute selector](https://developer.apple.com/documentation/coreaudio/kaudiodevicepropertymute)

## Implementation consequence for Open Dock

The existing shared `run_action` path already maps media actions to Enigo media-key events, so macOS can reuse it. Open Dock now declares Catalina as the bundle minimum, includes the required local-network usage description, explains Accessibility permission in the desktop UI, and forwards permission failures to the phone. Keep macOS playback state `Unavailable`; retain the phone's last Open Dock command as a visual prediction. Do not add a Swift bridge or MediaPlayer polling until Open Dock controls media playback itself or commits to a small, explicit list of app integrations. Validate the app bundle, media keys, local-network permission, and Enigo permission behavior on Catalina and a current macOS release before claiming the full supported range.
